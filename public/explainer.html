Details

Visitor's browser Tour 2

What it does

Loads the single-page app, sends a prompt to the API and shows the answer, or a recorded run when the live AI quota is used up.

Files

  • src/web/App.tsx
  • src/web/project.ts
  • project.json

Why it is built this way

The page is static assets served by the Worker, so it costs no Worker CPU. The Startup name, colors and problem come from project.json, so a new Project changes data, not layout.

Worker API (Hono) Tour 3

What it does

Serves /api/ask and /health. It validates the prompt, keys the visitor by a peppered hash, and hands the call to llm().

Files

  • src/worker/index.ts
  • src/worker/ratelimit.ts
  • wrangler.jsonc

Why it is built this way

One Worker holds every key and the database URL, so nothing secret ever reaches the browser. /health always answers 200 with {ok, db, sha} so the Pages front and the deploy smoke check can read why it is not ok.

llm(): free model chain Tour 4

What it does

Counts the call against a daily cap in Neon, then tries Workers AI, Groq and OpenRouter free tiers in order, and falls back to a recorded run with a banner.

Files

  • src/worker/llm.ts

Why it is built this way

Every model call goes through one function, so the $0 rule holds in one place: no database or a full day fails closed to demo mode instead of spending.

Neon Postgres Tour 5

What it does

Stores the daily call counter, the recorded demo runs and visitor submissions, one Neon project per Project.

Files

  • src/worker/db.ts
  • db/schema.ts
  • db/init.sql
  • db/rls.sql

Why it is built this way

Row-level security keys visitor rows on app.visitor, and the Worker connects as an app role that cannot bypass it. HTTP queries fit the Worker's short requests.

GitHub Pages front Tour 1

What it does

The link to share. It sends visitors to the live Worker when /health answers, and shows the recorded runs when it does not.

Files

  • pages/index.html
  • demo/runs.json

Why it is built this way

A free Worker or database can sleep or be retired; the Pages link and its recorded runs stay up, so an old link never shows an error.

ship.yml: build, publish, deploy Tour 6

What it does

Build runs the Claude Code agent with a read-only token. Publish, on a fresh runner, refuses protected-path changes, tests, builds and runs gitleaks before pushing. Deploy checks the review, placeholders, Pages and database size, then ships the Worker with its secrets and publishes Pages.

Files

  • .github/workflows/ship.yml
  • scripts/check-review.mjs
  • scripts/check-placeholders.mjs
  • scripts/provision-neon.mjs

Why it is built this way

Heavy work runs in GitHub Actions, never on a laptop, and the agent that writes the code never holds a deploy secret or a push token.

This explainer and the clip Tour 7

What it does

The project-explainer skill writes public/explainer.json; a script checks it and builds this page. A best-effort job turns the same facts into a short how-it-works video.

Files

  • .claude/skills/project-explainer/SKILL.md
  • scripts/build-explainer.mjs
  • scripts/build-clip.mjs

Why it is built this way

One fixed page format for every Project, readable from a file with no server, so each Project can be understood in about three minutes.
